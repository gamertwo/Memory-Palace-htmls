Important Rule

Memorize the code skeleton attached to the peg, not a totally different image every time. Reuse the same pegs on every arrays question so the chapter feels like one system.

Do and Do Not

Do

  • Memorize full syntax skeletons such as type name[SIZE]; and for (int i = 0; i < SIZE; ++i).
  • Say the peg word before writing the code shape.
  • Dry-run every loop with 3 to 5 values.
  • Use one page for one chunk of logic during revision.
  • Keep safe input habits like width-limited scanf.

Do Not

  • Do not memorize only the final output and skip the loop body.
  • Do not change peg words every day.
  • Do not write <= SIZE when you mean < SIZE.
  • Do not start array indexing from 1.
  • Do not forget that strings in C must end with '\\0'.

Flow For Writing Code

1. Read The Job

Ask whether the question wants storage, traversal, comparison, counting, swapping, or printing.

2. Pick The Pattern

Choose the skeleton: declaration, loop, if-check, function, or nested loop.

3. Write The Frame

Write the loop header and starter variables before the body details.

4. Fill The Update

Inside the loop, update total, max, count, temp, or found index.

5. Dry Run

Run the code mentally on three values and check the first and last index.
